Working with Events

Click any active time slot to open the Add Event dialog.

  • Fill in title, type, times, optional layer, responsible user, and invited persons.
  • Changing Start time auto-adjusts End to Start + 1 hour.
  • Drag an event block to reschedule it.
  • Click a block to open its Detail view (edit, delete, alarm, status).
  • You can set an inline alarm directly while creating or editing an event.
  • 📎 = file attached · ↻ = recurring · ✎ = edited
  • Non-overlapping events span the full column width for better readability.
📎

File Attachments

Any event can have one or more files attached to it — useful for orders, maps, briefing documents, images, or reference materials.

  • Open an event's detail view and click 📎 Attachments to upload files.
  • Accepted: any file type. Individual file size is limited by server configuration (default 32 MB).
  • Uploaded files are listed with name, size, uploader and timestamp.
  • Click a filename to download it. Admins and the uploader can delete attachments.
  • Events with attachments show a 📎 badge on the timeline block.
  • Templates include attachments: when you save a template, all attached files are copied into the template. When you apply the template, files are re-created on each new event automatically.
💬

Comments & @mentions

Leave text comments on any event to record decisions, share context, or flag issues for other team members.

  • Open the event detail view and scroll to the Comments section.
  • Type a comment and press Enter (or click Add) to post.
  • Use @username to mention a specific user — they receive an in-app notification.
  • Comments are timestamped and show the author's display name.
  • Team Leads and admins can delete any comment; others can only delete their own.
  • Comments are included in the Daily Briefing and AAR reports.
🗂

Layers

Layers are named overlays on the master timeline with their own color, visibility (Private / Groups / Public), and write access.

  • Click 🗂 Layers to open the quick-toggle popover — check/uncheck layers for immediate visual change.
  • When all layers are checked (default), everything is visible.
  • Master timeline events are always shown regardless of layer filters.
  • Manage layers (create, edit, share) in the Layers sidebar tab.
  • Layer visibility is per-user and persists across sessions.
  • Layers can be shared with specific Groups at read or read/write access level.
  • Team Leads and above can create, rename, and delete layers.
  • A layer color-codes event blocks for quick visual identification on the timeline.
📋

Templates

Templates capture a set of events (with relative time offsets) so an entire exercise or incident schedule can be reused and replayed in seconds.

  • Click 📋 Templates in the toolbar to open the template manager.
  • Save: all events in the current view (or a selected date range) are stored as a template. Attachments, phases, locks, and groups can all be included.
  • Apply: choose a base date/time (STARTEX) — all events are recreated at their original relative offsets from that moment.
  • Export / Import: download templates as JSON files for offline storage or sharing with other installations.
  • Private templates are visible only to you; Public templates are visible to all users (requires Ops Lead or Admin role to create).
  • Attachments are preserved: files attached to original events are copied into the template and re-created on every apply.
  • Templates can embed theme, language, operation mode, and terminology preferences that are applied when the template is loaded.
  • The example-templates/ folder in the distribution contains 31 ready-made templates (exercise scenarios, incident responses).
🔍

Filters & Presets

Use the filter bar (sidebar → Filters tab) to narrow down what is shown on the timeline without hiding anything permanently.

  • Filter by event type, status, participant (internal/external), responsible user, or free-text search on title/description.
  • Multiple filters combine with AND logic — only events matching all criteria are shown.
  • Filters are purely visual; they do not affect exports or reports.
  • Save as preset: give a filter combination a name and save it for quick recall. Presets are per-user.
  • Click a saved preset to apply it instantly; click it again to clear.
  • The active filter count is shown as a badge on the Filter button in the toolbar.

Alarms

Set an alarm while creating or editing any event, or from the Detail view using 🔔 Set Alarm.

  • Choose lead time (at event · 5 min · 10 min · 15 min · 30 min · 1 h · 2 h before).
  • When creating with invited persons, you can set the alarm for yourself only or for all invited.
  • Alarms appear as in-app pop-ups and in the Alarms sidebar tab.
  • Un-ACK'd alarms escalate: orange after 60 s, pulsing red thereafter.
  • Webhook users also receive a POST when an alarm fires.

Recurrence Patterns

Available patterns: Every 30 min · Hourly · Every 2/3/4 h · Daily · Weekly · Monthly · Quarterly.

Set a Recurrence End to limit repetitions. Recurring events show a ↻ icon. When deleting, choose to delete: this occurrence / this and all future / the entire series.

Recurring events are not shown outside your configured day hours to keep the view clean.

Synthetic Exercise Time

Ops Lead+ can define an Exercise Epoch — the real datetime that maps to Day 1 T+0. Click 🕐 T+ in the toolbar to toggle synthetic day headers.

  • The red current-time line shows an H+N label (hours since epoch).
  • Enable Day-hours only to count only hours within your configured day window.
  • Freeze / pause the timeline to stop synthetic time for planning (Ops Lead+).
  • Phases (Team Lead+): color-coded overlays showing exercise phases.
🔗

Webhook Notifications

Configure a personal webhook under Settings → Notifications / Webhook. When an alarm fires, a HTTP POST is sent.

  • Mattermost / Slack: sends {"text":"…"}
  • Generic: sends {"message":"…","event_id":…}
  • Click Test to verify the endpoint before saving.
🔑

SSO / OIDC Single Sign-On

Administrators can configure OIDC-based SSO so users log in via an external identity provider (Entra ID, Keycloak, Authentik, etc.).

  • Go to 🔌 Integrations → SSO / OIDC in the sidebar (admin only).
  • Provide the Issuer URL, Client ID, and Client Secret from your IdP.
  • Enable Exclusive mode to force all non-admin users through SSO.
  • SSO users are created automatically on first login with the configured default role.
  • SSO accounts display an SSO badge and cannot change their password here.
  • The legend panel shows real-time SSO status (active / inactive) for admins.
🔐

TLS / HTTPS

Serve Tidslinjal over HTTPS by providing a TLS certificate and private key.

  • Supply --tls-cert and --tls-key CLI flags, or set paths via Integrations → TLS in the admin panel.
  • CLI flags always take precedence over the stored config.
  • TLS changes take effect on the next server restart.
  • For self-signed certificates on internal networks, disable TLS Verify for syslog forwarding.
  • The legend panel shows whether TLS is configured (cert file set).
📡

Syslog Forwarding

Forward audit and application log messages to a remote syslog server.

  • Configure via Integrations → Syslog (admin only).
  • Transport: UDP (default, fastest), TCP (reliable), or TLS (encrypted).
  • Format: Classic RFC 3164 or structured JSON.
  • Default port: 514 (UDP/TCP) or 6514 (TLS).
  • Use Test to verify connectivity before saving.
  • App name, facility code, and TLS certificate verification are configurable.
✉

SMTP / Email Notifications

Tidslinjal can send email notifications for alarms and scheduled reports.

  • Configure via Integrations → Mail / SMTP (admin only).
  • Supports STARTTLS, TLS/SSL, or plain (no encryption) connections.
  • Set SMTP host, port, credentials, and a From address/name.
  • Use Test Email to send a confirmation message before saving.
  • Scheduled reports can be delivered to any email address once SMTP is enabled.
💬

Mattermost & Webhook Notifications

Each user can configure a personal webhook URL to receive push notifications for alarm events.

  • Go to Settings → Notifications / Webhook and enter your incoming webhook URL.
  • Choose webhook type: Mattermost / Slack (sends {"text":"…"}) or Generic.
  • Click Test to verify the endpoint.
  • Notifications fire when a user's alarm triggers.
  • The legend panel (admin) shows how many users have webhooks configured.
🗝

API Keys

API keys allow external tools and scripts to call the Tidslinjal REST API without interactive login.

  • Create API keys via Integrations → API Keys (admin only).
  • The key is shown only once on creation — copy and store it securely.
  • Send the key in the Authorization: Bearer <key> header.
  • API keys have a name and optional description for auditing.
  • Last-used timestamps help identify unused keys to rotate or revoke.
  • The legend panel shows the total count of active API keys.

Multi-Timezone Clocks

The header displays the primary real-time clock. You can add additional clocks for other time zones — useful for distributed teams or international exercises.

Adding a clock

  1. Click the + button to the left of the main clock in the header.
  2. Search for a city, country or IANA timezone name (e.g. London, America/New_York).
  3. Select from the suggestions and optionally edit the short label.
  4. Click Add. The clock appears immediately next to the main clock.

Removing a clock

Click the × button on the extra clock widget, or go to Settings → Date/Time Format → Additional timezone clocks and click Remove.

Detached clock window

Click the ⧉ button to open all clocks in a separate floating window. While detached:

  • The main clock area is hidden from the header to save space.
  • The detached window automatically follows the application's current theme (dark, light, camouflage).
  • Switch between digital and analog (round clock face with hour/minute/second hands) modes.
  • Choose a clock style: Standard, Minimal (transparent cards), or Compact (smaller cards).
  • Use the size slider to scale all clocks from XS to XL.
  • Each extra clock has its own × button to remove it directly from the detached window.
  • The detached window dynamically reflects changes to the clock list — no need to reopen it.

Additional clocks are saved per user and persist across sessions.

VCR seven-segment display

The clock display uses a retro VCR-style seven-segment digital format. Segment colors and thickness are configurable. A text display mode shows exercise labels or custom text.

Countdown & timer clocks

The detached clock window also hosts countdown timers and stopwatch timers with progress bars, alarms, and color customization. See the dedicated help sections for details.

Time Slot Locking

Operations leads and admins can lock time ranges to prevent editing of events in that window.

  • Click 🔒 Lock in the toolbar to open the lock manager.
  • Set start/end time, an optional reason, and scope (all layers, master only, or a single layer).
  • Locked slots are shaded with a diagonal stripe. Events inside cannot be moved, edited, or deleted.
  • Locks are fully undoable via the Undo button.

Reports

Click the 📄 Report button in the toolbar to generate an HTML report of the current events.

  • AAR — After Action Report, grouped by event status.
  • Per Layer — Events broken out by layer.
  • Timeline Snapshot — Full chronological list.

Filter by date range and visible layers. Times are formatted according to your language/locale setting. The report opens in a new browser tab for printing or saving.

Manual Backup & Restore

Admins can download a full ZIP backup and restore from it at any time. Go to the Admin sidebar tab → 💾 Backup.

  • Download backup: creates a ZIP containing all JSON data files (events, users' preferences, templates, layers, groups, alarms, phases, locks, comments, versions, etc.).
  • Restore: upload a previously downloaded ZIP. The server overwrites data files immediately. A restart is recommended for changes to take full effect.
  • For security, restore does not overwrite users.json (passwords), sessions.json, apikeys.json, oidc.json, or mail.json.
  • Uploaded file attachments (in the data/attachments/ folder) are not included in the ZIP and must be backed up separately.
  • All backup and restore actions are recorded in the Audit Log.
🔄

Gradual (Automatic) Backup

The Gradual Backup feature takes rolling automatic snapshots at a configurable interval, making it easy to recover from accidental deletions, resets, or bugs.

  • Enabled by default with a 15-minute interval and up to 48 retained snapshots (~12 hours of history).
  • Configure in Settings → Gradual Backup (admin only): toggle on/off, set the interval (5–60 min), and set the maximum number of retained snapshots.
  • Each snapshot is a ZIP file stored in data/snapshots/ on the server, named with a timestamp.
  • Use Snapshot now to immediately create a snapshot outside the regular schedule.
  • Browse the list of saved snapshots and click Restore to revert to a specific point in time.
  • Download any snapshot as a ZIP file for offline archival.
  • Old snapshots beyond the max snapshots limit are automatically pruned.
  • All snapshot creation, restoration, and deletion actions are recorded in the Audit Log.

Use cases: recover from an accidental admin reset, undo a bulk delete, restore a clean state before a new exercise begins, or roll back after a configuration error.

📜

Audit Log

Tidslinjal records all significant actions in an append-only audit log visible to Team Leads and above.

  • Access via the Audit sidebar tab (requires Team Lead role or higher).
  • Each entry shows: timestamp, user, action type, entity type/ID, and a human-readable summary.
  • Actions logged include: event create/edit/delete, user management, backup/restore, login/logout, template save/apply, lock create/delete, phase changes, and more.
  • The log is capped at 10,000 entries; oldest entries are pruned automatically.
  • Audit data is included in full backup ZIPs.
  • The audit log can be forwarded to a remote syslog server for long-term retention (see Syslog section).

Countdown Timers

Countdown timers count down to a specific target time, with visual progress tracking and alarm notifications.

Creating a countdown

  1. Click + Countdown in the clock toolbar (detached clock window or header clocks).
  2. Set the target time, or select from an event's start/end time.
  3. The countdown displays remaining time with a progress bar showing percentage complete.

Countdown features

  • Visual progress bar fills as time progresses toward the target.
  • When the countdown reaches zero, an alarm notification fires with an audible alert.
  • Click ACK to acknowledge the expired countdown and dismiss the alarm.
  • Expired countdowns show overtime styling (red progress bar) if not acknowledged.
  • Each countdown can be detached to its own standalone window via the ⧉ button.
  • Countdowns sync across all open windows (main and detached).
⏲

Stopwatch Timers

Stopwatch timers count up from zero with an optional target duration, progress bar, and alarm.

Creating a timer

  1. Click + Timer in the clock toolbar.
  2. Set the target duration using hours/minutes/seconds inputs, or use preset buttons (5, 10, 15, 30, or 60 minutes).
  3. Choose whether the timer should stop or continue after reaching the target.
  4. Optionally enable a sound alarm with selectable sound type.
  5. Click Start to begin timing.

Timer features

  • Visual progress bar shows elapsed time vs. target duration.
  • If "continue after target" is enabled, the progress bar switches to an overtime indicator when the target is exceeded.
  • Pause and resume controls are available during timing.
  • Each timer can be detached to its own standalone window via the ⧉ button.

Color customization

Use the color pickers in the clock toolbar to customize display colors:

  • BG — Background color of the clock display area.
  • CD — Accent color for countdown timers.
  • TM — Accent color for stopwatch timers.

Decision Log

The decision log provides structured tracking of decisions made during operations or exercises.

  • Access the decision log from the sidebar or the Tools menu.
  • Click + New Decision to create a decision entry with title, description, rationale, and responsible person.
  • Decisions follow a status workflow: Proposed → Approved / Rejected.
  • Attach files to decisions for supporting documentation.
  • Team Lead+ can approve or reject decisions.
  • The decision log can be detached to a standalone browser window for multi-monitor use.
  • Full i18n support — available in English, Swedish, and French.
📓

Log Book

The log book maintains a chronological record of operational events, observations, and notes during exercises or incidents.

  • Open the Log Book from the sidebar Logs tab.
  • Click + New Entry to add a timestamped log entry.
  • Entries are automatically attributed to the creating user with a timestamp.
  • Entries display in reverse chronological order for easy review.
  • Useful for maintaining a running operations record, shift handover notes, or incident observations.

Resource Management

Manage operational resources — rooms, buildings, IT services, and data centers — from the sidebar.

Resource types

  • Rooms — Meeting rooms, operations centers, command posts. Supports room type categorization.
  • Buildings — Physical buildings and facilities.
  • Computer Services — IT infrastructure, servers, and network resources.
  • Data Centers — Data center facilities.

Creating resources

  1. Open the Resources tab in the sidebar.
  2. Select the resource type sub-tab.
  3. Click + Add to create a new resource.
  4. Fill in name, description, location (latitude/longitude), upload an image, and select a map symbol/icon.
  5. Click Save.

All resources are clickable — click any resource item in the list to open its detail/edit view.

Custom resource types

Admins can create custom resource categories (e.g. Vehicles, Radios, Generators) via the Manage Types sub-tab. Each custom type appears as its own tab in the Resources pane.

Ready Check

In Settings, team leads can enable a Ready Check that verifies all activities have changed from "planned" to another status before a set time. This ensures all preparations are complete before the operation starts. The check time can be set as an absolute time or as a number of minutes before the epoch/STARTEX.

Resources with location coordinates appear as markers on the Map Projection and can be toggled by type.

🗺

Map Projection

The map projection provides an interactive geographic view of meetings, users, and resources using Leaflet.js.

  • Open from the Map toolbar button or detach to a separate window.
  • Tile layers — switch between OpenStreetMap, Topographic, Satellite, and Dark map styles.
  • Resource overlays — toggle visibility of Rooms (🏠), Buildings (🏢), IT Services (💻), and Data Centers (🖥) as map markers.
  • Meeting markers — physical meetings with coordinates are plotted automatically.
  • User markers — user locations shown when geolocation data is available.
  • Address search — type an address in the search bar to geocode and zoom to that location.
  • GeoJSON/KML import — click Import to load external geographic data files as overlay layers.
  • Fit All — auto-zoom to show all visible markers on the map.
  • Layers panel — click Layers to toggle individual overlay layers on/off.
  • The map legend shows color-coded marker types for reference.
🪟

Detachable Windows

Several views can be detached to standalone browser windows — ideal for multi-monitor setups during exercises or incident response.

Detachable views

  • Clocks — Click ⧉ in the header to detach all clocks, countdowns, and timers to a separate window.
  • Sidebar — Click ⧉ on the sidebar to open it in its own window with all tabs.
  • Decision Log — Detach from the Tools menu or sidebar.
  • Map Projection — Open the map in a separate window for a dedicated geographic display.
  • Individual Timers — Each countdown or stopwatch timer can be detached individually.

Cross-window synchronization

  • Theme changes propagate to all detached windows automatically.
  • Language settings sync across all windows.
  • Data updates (new events, timer ticks) are reflected in real time.
  • If the main window is closed, detached windows fall back to API-based data loading.
🔌

Event Connectors

Tidslinjal includes an integration framework for ingesting events from external systems.

  • STIX/TAXII connector — ingest cyber threat intelligence feeds and automatically create timeline events from threat indicators.
  • Syslog connector — receive syslog messages and convert them to timeline events for incident timelines.
  • Connectors are configured in the Integrations sidebar tab (Admin / Ops Lead).
  • Incoming data is processed through the event bus with configurable routing and mapping rules.
  • The ingestion API endpoint allows external systems to push events directly via REST.
  • Connector metrics are available for monitoring throughput and errors.
